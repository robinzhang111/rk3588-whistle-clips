# 板载咪头受控录音（聊天 04）

当前状态：设备检查和 1 秒丢弃数据探测通过，20 秒受控录音及听辨尚未验收。不安装依赖，不调整 mixer，不启动检测。

## 操作条件

板型由设备树核实为 LubanCat-5 V2。官方规格书说明咪头位于 3.5 mm 耳机孔旁，V2R0 原理图标记 P1。当前 Line 2 差分输入、Main Mic=on、Headset Mic=off、Capture Mute=off，左右模拟增益 +9 dB、数字增益 0 dB。用户已确认耳机孔空着、咪头无遮挡。不要触碰带电元件或直接向咪头吹气。

在现有板端 SSH 终端粘贴下方完整命令。5 秒准备后看到“开始”再操作；20 秒后自动结束，不需要 Ctrl+C。声音顺序：

1. 安静约 3 秒。
2. 距咪头约 20–30 cm 正常说：“这是鲁班猫板载麦克风测试，一二三”。
3. 停约 2 秒，距咪头约 50 cm 间隔约 1 秒拍手三次。
4. 保持安静，等待“结束”。本轮不必吹哨。

命令采用声卡名称，48 kHz/16 位/双声道直接硬件采集；立体声格式不代表板载有两个独立麦克风。新会话存在时拒绝运行，不删除重录目录。若报设备占用，保留报错并回到本聊天定位，不强行停止其他服务。

```bash
(
set -eu
base=/home/basketclip-project/stage2/data
session=mic-rec-20261010-01
if fuser -s /dev/snd/pcmC0D0c; then
  echo '采集设备正在使用，停止本次操作'; exit 1
fi
mkdir -p "$base"
mkdir "$base/$session"
cd "$base/$session"
amixer -c rockchipes8388 contents > mixer-before.txt
{ date -u --iso-8601=ns; timedatectl status; ntpq -pn; } > clock-before.txt 2>&1
printf '%s\n' 'arecord -D hw:CARD=rockchipes8388,DEV=0 -t wav -f S16_LE -r 48000 -c 2 -d 20 -v controlled.wav' > command.txt
echo '5 秒准备；看到开始后，安静、说指定语句、停顿、拍手三次、安静'
sleep 5
echo '开始：20 秒录音'
/usr/bin/python3 -c 'import time,json,datetime; print(json.dumps(dict(marker="before_arecord",utc=datetime.datetime.now(datetime.timezone.utc).isoformat(),realtime_ns=time.time_ns(),monotonic_ns=time.monotonic_ns())))' > timing.jsonl
if arecord -D hw:CARD=rockchipes8388,DEV=0 -t wav -f S16_LE -r 48000 -c 2 -d 20 -v controlled.wav > arecord.log 2>&1; then
  rc=0
else
  rc=$?
fi
/usr/bin/python3 -c 'import time,json,datetime; print(json.dumps(dict(marker="after_arecord",utc=datetime.datetime.now(datetime.timezone.utc).isoformat(),realtime_ns=time.time_ns(),monotonic_ns=time.monotonic_ns())))' >> timing.jsonl
printf '%s\n' "$rc" > exit-code.txt
amixer -c rockchipes8388 contents > mixer-after.txt
echo "结束：arecord exit=$rc"
cat arecord.log
if test -f controlled.wav; then
  stat -c '%n %s bytes' controlled.wav
  sha256sum controlled.wav > SHA256SUMS
  cat SHA256SUMS
fi
exit "$rc"
)
```

这是使用板端现有工具的诊断命令，不在板卡维护辅助源码。命令开始/结束时刻不是首样本/末样本硬件采集时间；两次 Python 启动及调度也引入间隙。首样本采集延迟待验证，不能把 before_arecord 直接当作精确音频 UTC 起点。

## 结束后的检查

在本聊天回复“录完了”，说明是否完整说了指定语句、实际拍手次数，是否发生其他声音或操作中断。随后由本聊天只读检查板端结果，通过独立 SCP 下载本会话（不与源码上传混用），核对大小和 SHA256。

- 板端原件：`/home/basketclip-project/stage2/data/mic-rec-20261010-01/controlled.wav`。
- 电脑下载目标：`C:\path\to\basketclip\阶段2_离线哨声检测\data\mic-rec-20261010-01\controlled.wav`。
- 诊断/报告：阶段二 `outputs/mic-check-20261010-01/` 及后续录音会话报告目录。

下载后检查 WAV 实际采样率、声道、样本帧数、时长、可读数据长度及逐声道幅值/削波；播放原件，请用户确认指定语句与三次拍手能辨认、是否有妨碍使用的失真。非零幅值不能代替人工听辨或输入来源证据；未确认时保持待验收。
