## NPU 子任务：转换、实机运行与本文件行为对照通过

官方 [RKNN-Toolkit2](https://github.com/airockchip/rknn-toolkit2) 支持 RK3588；[2.3.2 发布页](https://pypi.org/project/rknn-toolkit2/2.3.2/) 提供 cp311 ARM64 wheel，但说明列出的系统为 Ubuntu，本机 Debian 兼容性需要实测。下载 wheel API 明确支持 load_tflite、rk3588 target 和不做整数量化的 float16 路径。

本地 `export_whistle_tflite.py` 另存原 H5 的 float32 TFLite，无训练、量化或改权重。第一次直接用中文 H5 路径触发 TensorFlow 路径解码错误，保留失败日志；沿用已验证 h5py 文件对象方式后，在 export-tflite-02 完成导出。中间模型 SHA256：651aea572ae35cb2146d64de13b1737c5952055208e20f4ba9e446c091a4bf10。275 个相同特征上最大分数差 1.3709068298339844e-06，0.65 决定及事件窗口位置一致。模型包含卷积、池化、LeakyReLU、ELU、全连接和 Logistic；导出成功不代表 NPU 支持已通过。

板端检查：RKNPU 驱动 0.9.8，/usr/lib/librknnrt.so 版本 2.3.0；原系统 Lite2 元数据 2.3.2。随后独立 Lite2 2.3.2 环境实际初始化此模型、查询 SDK 和推理通过，当前组合对这份模型取得运行证据；不由包版本推出所有模型兼容。未替换系统驱动/Runtime，转换与 Lite2 环境均不继承系统 NumPy 2.4.1。

Toolkit2 指定 onnxoptimizer 0.3.8，官方 [PyPI 发布](https://pypi.org/project/onnxoptimizer/0.3.8/) 没有 ARM64 wheel，下载原版源码构建。板端已有 gcc/g++/cmake，缺 Python.h；下载并核对 [Debian 官方开发头文件](https://packages.debian.org/bookworm/arm64/libpython3.11-dev/download)，仅解包至新部署目录 headers，不安装系统包。第一次元数据构建缺 pytest-runner，保留失败日志；补原构建要求后两线程编译通过，生成 wheel SHA256：bf61f8fbf5671ce7f4731fdba7336ac05dae3566e2f73cf29b5f9c7df02e4646。Toolkit2 实际导入和 pip check 通过。

首次 load_tflite 明确失败：`unsupported tflite on arm64 platform`，保存 rknn-convert.log 与 board-npu/conversion-fp16/conversion.json；不把 API 方法存在当 ARM64 支持。按授权转为 ONNX 路线，原 TFLite 和失败材料保留。
