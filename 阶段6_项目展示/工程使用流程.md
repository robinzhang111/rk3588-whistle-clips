# 08工程使用流程：受控播放最小入口

2026-10-15新增：本次比赛不带电脑时，改用[REC现场操作卡](./不带电脑的10分钟现场试测.md)。下面保留电脑受控播放流程，不适用于本次无电脑试测。

2026-10-15。本页是当前使用入口。**本轮仅本地工程交付；以下现场操作由用户另行决定何时执行，本轮未连接、部署或新采集。**

适用范围：电脑扬声器播放原视频前10秒，板卡用户按键采集，固定16倍/当前FP16 RKNN/0.65/v1，采后核查标签与软件播放记录，再截取原视频。正常不保存或上传连续音频。独立相机与任意录像的真实时间映射不在此入口的验收范围。

03历史会话的限定结论见[03验收](./03受控实机核心链路功能验收.md)。COMPAT采样时间和浏览器播放时间的总误差未知；约40毫秒仅历史播放拟合内部残差。精确UTC、独立相机同步、严格无丢样、长稳、识别准确率、性能和完整无人值守产品均未验收。

## 已有工具与本轮最小缺口

| 步骤 | 复用 | 本轮补齐 |

| 电脑服务 | controlled_playback.py、eventlink.Store/server | 通用会话配置、按需前台启动、日志、同会话状态/停止核查 |
| 用户按键采集 | start_software_time.py | 生成匹配会话的启动脚本；只生成，不自动上传/运行 |

| 人工确认 | 用户实际播放确认 | 独立review记录，默认pending |

## 1. 本地准备，不启动服务

在电脑PowerShell执行。Python使用现有环境；本入口只需标准库及已有FFmpeg/ffprobe，不需要电脑加载NPU或模型。不要安装新依赖。

```powershell
Set-Location 'C:\path\to\basketclip'
$python = (Get-Command python).Source
$env:PATH = "$PWD\tools\ffmpeg-9.0.2-essentials_build\bin;$env:PATH"
$flow = "$PWD\阶段6_项目展示\session_flow.py"
$session = 'core-live-playback-20261015-04' # 示例；已存在就换新的编号
$dir = "$PWD\阶段6_项目展示\outputs\$session"
$video = "$PWD\data\new_video\5710e5b0e5691924647f88c18a8174b6.mp4"
$pcAddress = '192.0.2.10' # 历史地址；现场先核查本机实际网卡地址
& $python -B $flow prepare --directory $dir --session $session --bind $pcAddress --video $video
```

成功生成session.json、由原视频直接生成并解码核验的preview.mp4、run-board.sh。输出目录末级名称必须等于会话编号；阶段一/二/六标准输出下已有同名会话或目标目录已存在时拒绝复用。预览与原视频哈希绑定。本受控入口要求原视频及格式首PTS为0；不支持的素材直接拒绝，不猜偏移。

准备失败保留目录与FFmpeg错误；换新编号排查，不删旧目录重试。不要再使用03历史启动器或手动给电脑、板端分别填写不同会话。

## 2. 后续现场：先检查板端，再准备新启动脚本

板卡连接按[阶段零SSH说明](../阶段0_环境准备/SSH连接说明.md)。该页地址/路径是历史快照；现场复核身份、网络、源码版本、模型哈希、PCM占用和运行进程。不要结束其他会话。

以下只上传本次新启动脚本，不上传数据、权重或输出。新脚本仍调用已部署的runtime-software-labels-20261015-01及现有venv；不假定它们目前仍存在或与本地一致。若版本或设备配置不符，停止，回08/04C核查，先本地验证再部署，不现场维护另一套源码。

```powershell
$key = 'YOUR_SSH_IDENTITY_FILE'
$board = 'boarduser@192.0.2.10'
ssh -i $key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes $board 'hostname; pgrep -af "start_software_time|board_runtime|sampling_probe"; cat /proc/asound/card0/pcm0c/sub0/status'
$remote = "/home/basketclip-project/stage2/runtime-software-labels-20261015-01/run-$session.sh"
ssh -i $key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes $board "test ! -e '$remote'"
if ($LASTEXITCODE -ne 0) { throw '远端脚本已存在或连接失败；不要覆盖' }
scp -i $key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes "$dir\run-board.sh" "${board}:$remote"
ssh -i $key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes $board "sha256sum '$remote'; bash -n '$remote'; bash '$remote' --check-only"
Get-FileHash "$dir\run-board.sh" -Algorithm SHA256
```

人工核对两端脚本SHA256一致，bash语法和check-only都成功。check-only不打开采集、不创建正式输出或console日志；正式启动时板端会拒绝已存在输出/console日志。脚本只接受可选--check-only，不能借额外参数覆盖会话或模型。板端源码及ABI/重采样依据应沿用既有核对方法；本轮仅验证生成逻辑，未现场执行上述命令。

## 3. 用户准备就绪时才启动电脑

准备好马上进行本次测试后，在电脑前台PowerShell执行，并保持窗口打开：

```powershell
& $python -B $flow start --directory $dir
```

服务绑定成功后打印READY并打开本机页面；看到“视频已就绪”再进入下一步。局域网8765只接四字段标签，127.0.0.1:8766只供本机播放与控制。原服务若占用端口则报错并保存日志，不关闭其他进程。

服务运行窗口输出同时保存pc-console.log，实际PID/开始时间在pc/service-ready.json。900秒期限从用户本次启动起算，不从准备脚本时起算。超过900秒自动结束；页面缓存不能证明服务仍在运行。若服务过期或页面打不开，停止本次操作、保留目录并换新编号；不要在无服务时采集，也不要改用其他播放器补猜起点。

在另一个电脑PowerShell窗口重设第1节变量后，执行：

```powershell
& $python -B $flow live-status --directory $dir
```

应返回本次session、实际pc目录、stopping=false、播放记录数和电脑已提交标签数。状态请求必须核对本机正在运行的会话，旧READY文件不是在线证明。本轮尚未现场验证板端到电脑的可达性；后续现场须按阶段三方法确认，不发送伪事件充当正式测试。

## 4. 用户按键开始与正常停止

用户在自己的板卡交互终端执行（将示例编号替换为第1节的编号）：

```bash
bash /home/basketclip-project/stage2/runtime-software-labels-20261015-01/run-core-live-playback-20261015-04.sh
```

显示等待空格后，由用户按空格开始；然后在电脑页面点击“从0开始播放并记录”。助手不得代按或远程代启动。板端第一次空格起最多10秒，第二次空格可提前正常停止；页面独立最多播放10秒，也可点停止。页面不控制板卡。

不要暂停后继续、拖动进度、改变速率、另开播放器或刷新页面。卡顿、跳转、暂停、异常时间或缺少记录时，保留失败现场，不猜播放起点、不用候选反推同步点、不反填UTC。

等待板卡最终状态及资源释放。原console在板端outputs/<session>.console.log；六份采集/事件原件在outputs/<session>/。closed只说明生命周期结束；另看automatic_labels的saved/submitted/pending_event_ids/all_acknowledged。0候选、0待发不能验收标签通信或片段。

板端收尾后，在电脑第二窗口执行正常关闭：

```powershell
& $python -B $flow stop --directory $dir
```

命令先核对当前服务会话与目录，再请求结束。等待第一窗口打印CLOSED，核对pc/service-closed.json。它保存关闭原因（用户请求、900秒过期、中断或错误），同时导出pc/received-events.jsonl。停止命令失败时不要按PID猜杀其他进程；可在本次前台窗口Ctrl+C收尾，再检查日志。不要仅关播放页代替关闭服务。

## 5. 结果独立下载与接收标签导出

电脑执行。本命令是明确的SSH/SCP操作；prepare/start/status/finish从不连接板卡。

```powershell
& $python -B $flow download --directory $dir --host $board --identity $key
& $python -B $flow status --directory $dir
& $python -B $flow export --directory $dir
```

下载仅取六份原件及本次console日志到新board-originals，先后核对远端哈希与本地哈希，记录download-verification.json；不上传、删除、移动任何板端数据。失败保留部分下载，禁止直接覆盖重试。必须确认采集已经停止、资源已释放；下载状态不是closed会报错。

export以只读模式查询SQLite，生成根目录received-events.jsonl，不依赖可能过期的自动导出快照。已导出则拒绝覆盖；若已导出且库未变，后续finish会复用并核对它。数据库不存在、会话不符直接报错，不创建空库。

## 6. 播放核查、映射、截片与人工确认

```powershell
& $python -B $flow finish --directory $dir
& $python -B $flow status --directory $dir
```

finish要求电脑服务已正常收尾、板端原件哈希匹配、非空标签与电脑四字段逐条一致。新播放记录还必须同会话且连续编号完整。只取实际playing到明确停止的连续区间；启动阶段的seeking/waiting可保留，但playing后出现暂停、跳转、等待、卡顿、第二次playing或速率变化，直接拒绝映射。无playing、无停止、非零起播位置、乱序/丢号、媒体冻结、就绪不足或时间异常均拒绝。

连续性门限：相邻有效观测间隔不超过0.35秒、墙钟与performance相对变化差不超过0.05秒、两点比例0.95～1.05、内部残差不超过0.15秒。这些是保守的软件异常门禁，不是实测同步精度；没有记录无法证明的时间区间仍拒绝外推。历史03记录没有新编号，保留其原验收，不强行改写历史为新格式。

通过后保存playback-check.json和playback-mapping.json，显式以software_playback_observation模式调用原basketclip.mapped。仍按起点前5秒后3秒截原视频，片头尾截短；窗口跨出已观测区间拒绝。clips/manifest.json逐条记录completed/rejected/failed；成功片段进一步完整解码，保存clip-verification.json与summary.json。

出现错误，finish.log、failure.json及已有产物保留，不覆盖重试、不自动重新采集。若已出现失败文件，应先按原始原因排查；缺失播放证据不能补造，下一次真实测试换新编号。可对已经保存的标签单独补发（下一节），不改变原会话失败结论。

用户逐个播放clips/*.mp4，检查内容与位置，然后才记录实际意见。例如用户明确接受后执行：

```powershell
& $python -B $flow review --directory $dir --decision accepted --note '已逐个播放，内容和位置符合预期'
& $python -B $flow status --directory $dir
```

不符合则用--decision rejected及实际原因。工具不自动替用户确认；human-review.json另存且拒绝覆盖。summary.json是截片时快照，最新人工结论用status查看。

| 状态 | 含义 |
|---|---|
| labels_submitted | 板端原采集进程已提交给发送队列的数量，不等于收到ACK |
| original_process_all_acknowledged | 原进程结束时的ACK状态，补发后不改写 |
| pc_committed_labels / pc_confirmed | 电脑SQLite已保存数量 / 非空板端标签与电脑逐字段一致；不证明原进程收到ACK |
| clips_generated | manifest已完成且文件存在的片段数；完整解码证据另见clip-verification |
| clips_full_decode_verified | 已完整解码且当前文件哈希仍匹配的片段数 |
| clips_rejected_or_failed | 有界映射拒绝或截取失败，不自动忽略 |
| human_confirmation | 默认pending，用户实际意见另存 |
| full_product_accepted | 恒为false，本入口不验收完整无人值守产品 |

## 7. 已保存标签补发，不重新采集

先在仍有效的本次服务窗口内检查接收器；若原服务已经关闭，单独开启同一会话的恢复接收器，使用新库，保留原库：

```powershell
$recovery = "$dir\recovery-01"
if (Test-Path $recovery) { throw '恢复目录已存在；换recovery-02并保留原目录' }
New-Item -ItemType Directory -Path $recovery | Out-Null
& $python -B .\阶段3_实时传输\eventlink.py --stage1 .\阶段1_离线手动触发 receive --bind $pcAddress --port 8765 --session $session --database "$recovery\labels.sqlite3" 2>&1 | Tee-Object "$recovery\receiver.log"
```

上面是前台阻塞命令，保持窗口打开；若原接收器仍占用端口，不能并行启动恢复接收器。用户在板端另一个终端仅执行upload，不运行采集/模型（替换编号和当前电脑地址）：

```bash
release=/home/basketclip-project/stage2/runtime-software-labels-20261015-01
python=/home/basketclip-project/stage2/deploy-20261013-01/venv-npu-run/bin/python
session=core-live-playback-20261015-04
set -o pipefail
set -o noclobber
"$python" -B "$release/阶段3_实时传输/eventlink.py" --stage1 /home/basketclip-project/stage1 upload --url http://192.0.2.10:8765/events --session "$session" --events "/home/basketclip-project/stage2/outputs/$session/events.jsonl" --drain-seconds 10 > "/home/basketclip-project/stage2/outputs/$session.replay-01.log" 2>&1
replay_status=$?
cat "/home/basketclip-project/stage2/outputs/$session.replay-01.log"
printf 'replay_exit=%s\n' "$replay_status"
```

检查实际label_saved回执、退出码与pending；非空事件且全部ACK才说明这次补发获确认。退出后队列不自动持久运行，必要时新编号日志重放完整文件，原SQLite去重/冲突检查复用。重复标签不变，发生时间不改成接收时间。板端replay日志另行scp到recovery-01/replay.log保留，核对哈希；不回写原status的pending。

```powershell
if (Test-Path "$recovery\replay.log") { throw '本地补发日志已存在，不覆盖' }
scp -i $key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes "${board}:/home/basketclip-project/stage2/outputs/$session.replay-01.log" "$recovery\replay.log"
Get-FileHash "$recovery\replay.log" -Algorithm SHA256
ssh -i $key -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes $board "sha256sum '/home/basketclip-project/stage2/outputs/$session.replay-01.log'"
```

恢复接收器Ctrl+C正常关闭后，在电脑新窗口核对恢复库：

```powershell
& $python -B $flow status --directory $dir --database "$recovery\labels.sqlite3"
```

只有尚未导出/finish的会话，才在第5/6节的export、finish命令加同一个--database路径，使用恢复库继续。若原来已有导出或处理尝试，保留原快照，以恢复日志和status为独立补发证据，不覆盖原失败产物。恢复库不能补回缺失播放记录；没有时间依据仍不映射。
