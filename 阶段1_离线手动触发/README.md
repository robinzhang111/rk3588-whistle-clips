# 阶段一：离线手动触发与赛后片段生成

篮球哨声事件与比赛录像自动片段记录系统。用于个人兴趣开发与简历项目展示。

REC实按、标签导出和已有录像模拟截取已有验收，真实采集同步待验收。2026-10-13默认采用统一UTC与录像实际采集时间映射，板端正常仅保存上传标签，不要求同步录音；两路音轨拍手仅调试/备用。后续模型部署成果见项目首页。

## 环境

- Python 3.8 或更高版本；基础版仅使用标准库，无第三方 Python 运行依赖。
- 电脑端视频检查与截取需要 `ffmpeg` 和 `ffprobe`，并加入 PATH。
- 当前截取采用 `libx264` 视频重新编码与 AAC 音频编码；FFmpeg 构建需包含这些编码器。
- RK3588 端手动事件记录不需要 FFmpeg。
- 上位机系统、LubanCat 5 系统、相机和麦克风型号均待确认。

先进入 `阶段1_离线手动触发` 目录再运行。以下所有命令与相对数据路径均以该目录为基准：

```text
python -m basketclip doctor
python -m unittest discover -s tests -v
```

## 最小使用流程

1. 按约定只同步必要源码到板卡，启动相机录像并核查两端UTC及实际采集锚点，不要求板端独立录音。
2. 在 RK3588 运行手动记录器。输入 `m` 保存事件，输入 `q` 结束：

```text
python -m basketclip record --session game-001 --output data/game-001/events.jsonl
```

3. 将录像、标签与映射依据导入电脑，确定一个实际拍摄UTC对应的录像位置；相机时间信息或外部校准需核实，不直接用创建/按钮/上传时间。只有选择音轨备用校准时才提供同步录音。
4. 建立时间映射。以下时间与位置只是示例，必须替换为实际测量：

```text
python -m basketclip align --session game-001 --event-utc 2026-10-10T12:00:10Z --video-seconds 5 --output data/game-001/alignment.json
```

5. 检查视频，然后生成片段：

```text
python -m basketclip inspect --video data/game-001/video.mp4
python -m basketclip extract --video data/game-001/video.mp4 --events data/game-001/events.jsonl --alignment data/game-001/alignment.json --output outputs/game-001 --before 8 --after 5
```

片段与 `manifest.json` 写入输出目录。命令默认不覆盖已有文件；重复运行应选择新目录，避免修改原始材料。

现有align/extract仅保存/使用手工锚点，不自动读取相机时间。默认无需板端录音，但必须有可信UTC—视频位置映射，无依据时保持待对齐。音轨备用方式才需要带时间关系的临时录音。见[时间与留存方案](../docs/统一时间与最小音频留存方案.md)。

## 验收边界

程序按时间标签截取视频，不判断犯规，不自动执裁。计算结果正确不等于相机和事件时间已经同步。需在真实素材上测量最终定位误差，并检查关键帧、音视频同步、长时间漂移和片段可播放性。

本项目尚未选定开源许可证；参考第三方代码时需保留来源并核对相应许可证。
