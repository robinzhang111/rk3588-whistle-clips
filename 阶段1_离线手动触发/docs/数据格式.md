# 数据约定

## 事件：JSONL

一行一个事件，UTF-8，字段如下：

| 字段 | 含义 |
|---|---|
| `session_id` | 非空会话标识，需与对齐文件一致 |
| `event_id` | 会话内唯一正整数 |
| `event_type` | 当前允许 `manual_trigger` 和 `whistle` |
| `event_time_utc` | 显式 UTC 的 ISO 8601 时间，代表事件发生时刻 |

完全相同的重复记录会去重；同会话、同编号但不同内容会报错。阶段一支持离线导入，阶段三已有沿用四字段的网络接收/上传子任务。

## 对齐：JSON

`align` 命令保存会话、事件时间轴同步点 `anchor_event_utc`、视频同步点 `anchor_video_seconds` 和比例 `video_seconds_per_event_second`。

```text
视频事件秒数 = 视频同步点秒数 + (事件UTC - 同步点UTC) × 时间比例
```

单点时比例为 1；两点时按两个同步点的间隔拟合。所有位置单位均为秒。导入不同录像时必须重新核对映射。

2026-10-13锚点默认来自已核验录像实际采集UTC—媒体位置，不要求两路拍手音轨。现有align仅保存手工锚点，自动读取相机时间待实现。正常板端音频仅短时内存，不随标签上传；必要采样位置/时间源/误差依据另存会话诊断，本次不改四字段协议。见[时间与留存方案](../../docs/统一时间与最小音频留存方案.md)。

## 输出

- `event_000001.mp4`：事件片段。
- `event_000001.json`：该事件的目标位置、起止区间与处理状态。
- `manifest.json`：原始视频路径、视频时长、采用的时间映射、片段参数和所有事件结果。

状态包括 `completed`、`skipped`、`failed`；完成状态只说明程序处理成功。具体定位和媒体质量仍需人工检查。

示例目录中的时间和事件是合成测试材料，不是比赛数据或实验结果。
