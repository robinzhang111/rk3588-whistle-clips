# 离线手动版操作指南

## 1. 开始条件

2026-10-13默认：录像可播放，RK3588保存UTC事件，电脑建立有依据的实际拍摄UTC—媒体位置映射。正常不要求板端录音或视频音轨；拍手两路音轨为可选备用。见[时间与留存方案](../../docs/统一时间与最小音频留存方案.md)。

缺可信时间映射时可先用合成数据验证计算，不据此验收真实定位。下面align保存手工锚点，自动获取相机时间仍待实现。

## 2. 记录事件

在 RK3588 的 `阶段1_离线手动触发` 目录执行。电脑端也以该阶段目录为工作目录：

```text
python -m basketclip record --session game-001 --output data/game-001/events.jsonl
```

输入 `m` 并按回车记录事件，`q` 退出。事件时间是程序读取这条命令的时刻，不是开始输入字母的时刻。使用独立终端操作，暂不实现按钮或网络界面。

记录器采用启动时 UTC＋单调时钟差值，减少进程运行中系统时钟跳变的影响。应在启动前校准设备时间；此设计不能消除开机时的偏差或长时间漂移。

文件逐事件写入并刷新，已有路径拒绝覆盖。程序停止后再导出文件；一次运行使用独立会话，不追加到旧会话。

## 3. 导入与选择同步点

赛后导入录像、标签和时间映射依据，保留原件，默认不导入板端录音。通过可靠采集时间信息或有依据的外部校准确定锚点。

向现有align接口提供：

- `event-utc`：选定视频位置对应的实际采集UTC；参数名称保留，来源不必是拍手。
- `video-seconds`：该锚点在最终录像中的媒体位置，以秒表示。

两者不是文件创建、开始按钮或上传时间；需核查相机时钟、导出后时间位置及实际采集延迟。选择音轨备用方式时才另需同步录音和采样UTC依据，传播延迟等误差亦实测。

保存单点偏移：

```text
python -m basketclip align --session game-001 --event-utc 2026-10-10T12:00:10Z --video-seconds 5 --output data/game-001/alignment.json
```

检查中段和结束实际位置漂移，按需要使用已核验第二锚点。如果需要对连续时间轴做线性修正，可提供第二点：

```text
python -m basketclip align --session game-001 --event-utc 2026-10-10T12:00:10Z --video-seconds 5 --end-event-utc 2026-10-10T12:10:10Z --end-video-seconds 605.2 --output data/game-001/alignment_two_points.json
```

这些数值均为示例。两点修正不适用于录制中断、未知剪辑或时间跳变。当前程序只处理一个连续视频文件，多文件需要先明确连续性与映射，不能盲目拼接。

## 4. 检查和生成片段

```text
python -m basketclip inspect --video data/game-001/video.mp4
python -m basketclip extract --video data/game-001/video.mp4 --events data/game-001/events.jsonl --alignment data/game-001/alignment.json --output outputs/game-001 --before 8 --after 5
```

输出目录必须尚不存在。程序先验证全部事件，再创建目录。每个片段采用 H.264/AAC 重新编码；没有音轨时仅保存视频。前后时长可以改变，不保证所有视频格式均兼容。

越界事件标记为 `skipped`，不会悄悄截取录像边缘。有效事件在开头或结尾的片段会缩短，结果记录实际目标区间。编码失败记录为 `failed`，命令返回非零状态。

现阶段不合并重叠片段，按独立事件各自生成；不做 GUI、自动同步标记检测和相机控制。

## 5. 人工验收

- 每个 `completed` 片段实际播放并检查音视频。
- 用非同步标记的独立事件测量定位误差。
- 检查开头、结尾、重复事件和视频范围外事件。
- 记录编码耗时、输出时长和画质；程序中的 `completed` 仅表示 FFmpeg 成功退出，不能代替实测验收。
