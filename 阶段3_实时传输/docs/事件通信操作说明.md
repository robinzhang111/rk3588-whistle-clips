# 事件标签通信

Python >=3.8，仅标准库。HTTP 比自定义 TCP 少一层消息边界实现，易检查请求/状态；SQLite 提供事务保存和唯一键。SSH 隧道可作为网络受限时的替代，但本次实测是直接局域网 HTTP。

## 协议与边界

`POST /events`，UTF-8 JSON，最大 4096 字节。必须且仅含阶段一实际四字段：session_id（非空且匹配接收器指定会话）、event_id（1～9223372036854775807 的整数，不接受布尔值）、event_type（manual_trigger/whistle）、event_time_utc（显式 UTC ISO 8601）。编号上限是 SQLite 存储约束，未改写阶段一文件格式。未知字段明确拒绝；将来扩展事件字段需同步协议。

SQLite 表 events 保存 session、id、原事件 payload、首次 received 时间；唯一键为 (session,id)。事件时间保持原字符串，不用接收时间替代。同键、字段值相同（JSON 键顺序无关）返回同一确认；同键内容不同返回 HTTP 400，不覆盖。会话或字段错误也返回 400；存储失败返回 503，不发成功确认。

成功响应含 status=label_saved、session_id、event_id、received_time_utc、event_sha256。摘要针对排序且紧凑编码的原事件 JSON，发送端核对响应后移出待确认队列。确认仅代表标签事务提交成功，不代表录像、片段或检测成功，也不代表经过真实断电持久性测试。

每次 REC：阶段一先 write/flush/fsync，再通过可选 on_saved 回调把事件放入阶段三内存队列。网络线程串行发送；超时/网络错误/5xx/异常确认自动重试。4xx 明确记录拒绝，该事件保留待处理，不自动反复发送；后续事件仍可处理。网络断连时队列可增长，当前未做长期断网容量验收。

Ctrl+C 停止记录，默认最多等待 5 秒，再输出 pending_event_ids。原始事件 JSONL 始终保留。发送端没有持久化确认清单，也没有自动跨进程恢复；退出或重启后，用 upload 显式重发完整文件，已保存事件由电脑去重。接收数据库重开后的去重通过软件测试；断电、系统崩溃、损坏数据和长期运行未验收。

仅在受控局域网使用，绑定指定网卡。本版本没有认证或 TLS；不直接暴露公网。不自动修改网络/防火墙，不使用 HTTP_PROXY 环境代理。

## 电脑接收

从电脑阶段三目录运行。先确认地址/端口、会话名与数据库输出目录；以下为本次已核实配置：

```powershell
cd C:\path\to\basketclip\阶段3_实时传输
python eventlink.py --stage1 ../阶段1_离线手动触发 receive --bind 192.0.2.10 --port 8765 --session comm-rec-20261010-01 --database outputs/comm-rec-20261010-01/labels.sqlite3
```

接收器 Ctrl+C 结束。数据库可以重开，允许同会话去重；新验收用新会话和新目录，不覆盖已有会话。

## 板端记录与自动上传

部署位置：阶段三 /home/basketclip-project/stage3，依赖阶段一 /home/basketclip-project/stage1。源码在电脑维护。板端运行 /usr/bin/python3（本次 3.11.2）。

```bash
cd /home/basketclip-project/stage3
/usr/bin/python3 eventlink.py --stage1 /home/basketclip-project/stage1 record \
  --session comm-rec-20261010-01 --events data/comm-rec-20261010-01/events.jsonl \
  --url http://192.0.2.10:8765/events --board-button --drain-seconds 5
```

看到监听后短按 REC，Ctrl+C 结束；事件文件已存在会拒绝覆盖。测试时记录实际按下次数，不能用合成输入替代真实按键验收。不带 --board-button 可用 m 回车、q 退出做终端事件测试。

退出后显式补发：

```bash
/usr/bin/python3 eventlink.py --stage1 /home/basketclip-project/stage1 upload \
  --session comm-rec-20261010-01 --events data/comm-rec-20261010-01/events.jsonl \
  --url http://192.0.2.10:8765/events --drain-seconds 15
```

返回 0 表示本次队列无待确认事件；返回 1 或非空 pending 需排查。不能把程序启动、请求发送或 HTTP 日志单独当作端到端验收。

## 测试与部署

电脑阶段三运行 `python -m unittest discover -s tests -v`。板端阶段三运行 `STAGE1_PATH=/home/basketclip-project/stage1 /usr/bin/python3 -m unittest discover -s tests -v`。

tests/run_devices.py 是电脑控制的合成跨设备验证工具，参数 --key 仅用于已有 SSH 连接，不读取私钥内容；--host/--bind/--port/--session 必须显式给出。它创建全新 outputs 会话，在板端 stage3/data 保存终端合成事件，临时启停电脑接收器，做保存前断连和保存后未读取确认的故障注入。运行前核对进程和端口；不在真实采集运行期间执行。工具输出 commands.log、validation.json、板端下载事件与电脑接收事件；结束关闭临时监听。

部署只传 eventlink.py、相关测试及阶段一 basketclip/cli.py 最小回调改动。上传前检查进程并比对两端哈希，不传 data/outputs/缓存/私钥。下载结果独立执行。完整证据见验证记录。
