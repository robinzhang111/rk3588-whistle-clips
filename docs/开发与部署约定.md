# 本地开发与板卡部署

## 用户确定的流程

```text
电脑本地修改源码 → 本地测试 → 上传必要代码 → RK3588 运行验证
                                             ↓
                                下载事件与日志到电脑处理
```

本地项目 `C:\path\to\basketclip` 是维护源；板卡是运行和硬件验证环境，两份代码不会自动同步。

## 阶段一位置

| 内容 | 电脑 | 板卡 |
|---|---|---|
| 阶段目录 | `C:\path\to\basketclip\阶段1_离线手动触发` | `/home/basketclip-project/stage1` |
| 源码 | `basketclip/` | `basketclip/` |
| 测试 | `tests/` | `tests/` |
| 标签等数据 | 下载到本地独立会话目录 | `data/<会话名>/` |

## 每次修改

1. 检查本地实现和任务范围，修改本地源码。
2. 本地运行与修改相关的测试。
3. 检查板端相关程序是否运行；存在用户采集时说明影响并协调停止。
4. 上传本次必要文件，避免同步整个项目覆盖数据；传输失败时不要启动不完整更新。
5. 在板端执行适当的软件测试和硬件验证。
6. 将变更、部署路径、验证结果及未完成事项记录在本阶段文档。

只同步代码与必要配置，不上传 `__pycache__`、虚拟环境、`.git` 或原始音视频。不删除或覆盖板端 `data/` 和 `outputs/`。

当前使用已有 SSH 密钥配合 SCP。连接参数见 [SSH连接说明](../阶段0_环境准备/SSH连接说明.md)。

若发现板端有未同步回电脑的修改，先比较并保存，不直接覆盖。开发过程中遇到问题仍回到电脑修改，再部署复测。
